# 井関物流受払管理システム 設計書改修計画書 ver2.0

## 1. 改修概要

### 1.1 改修目的
生産受払システムにおける請求処理の精度向上と業務効率化を目的とした機能追加・改修を実施する。特に請求書フォーマットの改善と入力精度向上により、会計処理ミスの根本的防止を図る。

### 1.2 改修背景
**2025年3月発生事案を受けた再発防止対応**
- **発生事案**: 熊本生産グループでの発送運賃請求内容入力漏れによる会計処理ミス
- **根本原因**: 請求マスタで数量×単価入力後の自動計算機能がない
- **直接要因**: 担当者による請求金額入力漏れ
- **対応方針**: システム機能追加による人的ミスの防止

### 1.3 改修要件の出典
- **要件定義書**: 2025年4月18日付け「生産受払システム機能追加について」
- **依頼元**: 井関物流（窓口：小笠原氏、川本氏）
- **要求事項**: 機能追加費用概算見積もり、改修スケジュール提示
- **分析資料**: 新規改修要件詳細分析レポート（2025年6月3日作成）

### 1.4 ver2.0の主要追加要素
- **請求書フォーマット変更**: 金額と単位の間に区切り線を追加
- **RDLCレポート修正**: OutputSeikyuReportS.rdlcの詳細技術仕様
- **統合実装計画**: 5つの基本要件と請求書フォーマット変更の統合
- **詳細技術仕様**: 実装レベルでの具体的手順とテスト計画

## 2. 改修要件詳細

### 2.1 要件①：自動計算機能の追加
**概要**: 単価、数量入力後、金額が自動計算される機能を追加する

**詳細仕様**:
- 単価フィールドまたは数量フィールドの値変更時に金額を自動計算
- 計算式: 金額 = 単価 × 数量
- 小数点以下の処理: 四捨五入（円単位）
- 計算結果の即座反映
- エラーハンドリング: 非数値入力時の適切な処理

**対象設計書**:
- 受払システム_画面定義書(17.請求マスター登録).xlsx
- 受払システム_画面定義書(62.請求書出力).xlsx
- 受払管理システム_DB論理設計書.xlsx

**実装対象**:
- 請求マスター登録フォーム（VB.NET）
- 請求書出力フォーム（VB.NET）
- T_SEIKYU テーブル関連処理

### 2.2 要件②：入力促進機能の追加
**概要**: 単価、数量いずれか未入力の場合、入力を促す背景反転色付けする機能を追加する

**詳細仕様**:
- 単価フィールドが未入力（空白またはゼロ）の場合、背景色を警告色に変更
- 数量フィールドが未入力（空白またはゼロ）の場合、背景色を警告色に変更
- 入力完了時に背景色を通常色に戻す
- 警告色: 薄い赤色（#FFE6E6）または黄色（#FFFFCC）
- リアルタイム検証: フィールド離脱時の即座チェック

**対象設計書**:
- 受払システム_画面定義書(17.請求マスター登録).xlsx
- 井関物流 受払管理システム基本設計書.docx

**実装対象**:
- 請求マスター登録フォームのUI制御
- フィールド検証ロジック

### 2.3 要件③：金額フィールド保護機能
**概要**: 金額は手入力ができないようグレーアウトにする

**詳細仕様**:
- 金額フィールドを読み取り専用に設定
- 背景色をグレー（#F0F0F0）に変更
- フォーカス移動時にスキップ
- 自動計算結果のみ表示
- コピー機能は有効（参照用）

**対象設計書**:
- 受払システム_画面定義書(17.請求マスター登録).xlsx
- 受払システム_画面定義書(62.請求書出力).xlsx

**実装対象**:
- 請求関連フォームのUI制御
- TextBoxコントロールのプロパティ設定

### 2.4 要件④：単位項目の追加
**概要**: 請求書記載の数量の単位については、「単位」単独の項目を追加する

**詳細仕様**:
- 新規フィールド「単位」を請求マスターに追加
- データ型: VARCHAR(10) NOT NULL
- 初期値: 'その他'（既存データ移行時）
- 選択肢: 個、本、台、式、kg、m、㎡、その他（コンボボックス形式）
- 制約: CHECK制約による値の制限
- インデックス: 検索性能向上のため追加

**対象設計書**:
- 受払管理システム_DB論理設計書.xlsx
- 受払システム_画面定義書(17.請求マスター登録).xlsx
- 受払システム_画面定義書(62.請求書出力).xlsx

**実装対象**:
- T_SEIKYU テーブルスキーマ変更
- 請求マスター登録フォーム
- 請求書出力フォーム
- データベースアクセス層（DitDataAccess）

### 2.5 要件⑤：単位入力必須化
**概要**: 追加項目の単位は入力必須項目とし、未入力の場合背景色付けエラーにする

**詳細仕様**:
- 単位フィールドが未入力の場合、背景色を赤色（#FFE6E6）に変更
- 保存時に単位未入力チェックを実施
- エラーメッセージ表示: 「単位を入力してください」
- 入力完了時に背景色を通常色に戻す
- 必須項目マーク（*）の表示

**対象設計書**:
- 受払システム_画面定義書(17.請求マスター登録).xlsx
- 井関物流 受払管理システム基本設計書.docx

**実装対象**:
- 請求マスター登録フォームの検証ロジック
- エラーハンドリング機能

## 3. 請求書フォーマット変更要件（新規追加）

### 3.1 フォーマット変更概要
**目的**: 請求書出力時の金額と単位の視覚的分離による可読性向上
**対象**: 請求書出力レポート（OutputSeikyuReportS.rdlc）
**変更内容**: 金額と単位の間に区切り線「 | 」を挿入

### 3.2 具体的なフォーマット変更仕様

#### 3.2.1 現行フォーマット vs 修正後フォーマット

**修正前**:
```
数量: 1000円
数量: 15%
数量: 50個
```

**修正後**:
```
数量: 1000 | 円
数量: 15 | %
数量: 50 | 個
```

#### 3.2.2 技術的実装仕様

**RDLCレポート修正**:
- **対象ファイル**: `OutputSeikyuReportS.rdlc`
- **修正対象**: 数量表示式の変更
- **現行式**: `Format(Fields!SURYO.Value,"#,###") & Fields!TANI.Value`
- **修正後式**: `Format(Fields!SURYO.Value,"#,###") & " | " & Fields!TANI.Value`

**データソース連携**:
- **T_SEIKYUテーブル**: 新規TANIフィールドとの連携
- **単位表示**: 要件④で追加される単位フィールドの値を使用
- **既存単位定数**: 「円」「%」から新単位フィールドへの移行

### 3.3 実装詳細仕様

#### 3.3.1 レポートレイアウト変更
1. **テキストボックス修正**
   - 数量表示部分の式を更新
   - 区切り文字「 | 」の追加
   - フォント・サイズの統一性確保

2. **表示幅調整**
   - 区切り文字追加による表示幅の拡張
   - レイアウト全体のバランス調整
   - 印刷時の改行位置確認

3. **条件分岐処理**
   - 請求タイプ別の単位表示制御
   - 空値・NULL値の適切な処理
   - エラー時のフォールバック表示

#### 3.3.2 要件④との統合仕様

**単位フィールド連携**:
- **新規単位フィールド**: T_SEIKYU.TANIからの値取得
- **表示優先順位**: 
  1. 新規単位フィールド値
  2. 請求タイプ別デフォルト値（円/%）
  3. システムデフォルト値

**データ移行対応**:
- **既存データ**: 請求タイプに応じた単位値の自動設定
- **新規データ**: 単位フィールド必須入力による値保証
- **互換性**: 旧フォーマットとの並行運用期間の考慮

## 5. 実装方針

### 5.1 VB.NET アプリケーション修正

#### 5.1.1 請求マスター登録フォーム
```vb
Private Sub CalculateAmount()
    If IsNumeric(txtTanka.Text) AndAlso IsNumeric(txtSuryo.Text) Then
        txtKingaku.Text = (CDec(txtTanka.Text) * CDec(txtSuryo.Text)).ToString("N0")
    End If
End Sub

Private Sub ValidateFields()
    If String.IsNullOrEmpty(txtTanka.Text) OrElse CDec(txtTanka.Text) = 0 Then
        txtTanka.BackColor = Color.FromArgb(255, 230, 230)
    Else
        txtTanka.BackColor = SystemColors.Window
    End If
    
    If String.IsNullOrEmpty(txtSuryo.Text) OrElse CDec(txtSuryo.Text) = 0 Then
        txtSuryo.BackColor = Color.FromArgb(255, 230, 230)
    Else
        txtSuryo.BackColor = SystemColors.Window
    End If
    
    If String.IsNullOrEmpty(cmbTani.Text) Then
        cmbTani.BackColor = Color.FromArgb(255, 230, 230)
    Else
        cmbTani.BackColor = SystemColors.Window
    End If
End Sub
```

#### 5.1.2 データベースアクセス層

```vb
Private Const SQL_UPDATE_SEIKYU As String = _
```

```sql
ALTER TABLE T_SEIKYU

ALTER TABLE T_SEIKYU 
ADD CONSTRAINT CK_T_SEIKYU_TANI 
CHECK (TANI IN ('個', '本', '台', '式', 'kg', 'm', '㎡', 'その他'));

CREATE NONCLUSTERED INDEX IX_T_SEIKYU_TANI ON T_SEIKYU (TANI);

UPDATE T_SEIKYU SET TANI = 'その他' WHERE TANI IS NULL OR TANI = '';
```

## 12. 注意事項・リスク要因

### 12.1 重要な確認事項
1. **物流内確認**: 要件⑤について物流内確認後DIT連絡との記載
2. **既存改修との重複**: 同様の機能が既に設計済み
3. **請求書フォーマット**: 顧客への事前通知が必要
4. **データ整合性**: 単位フィールド移行時の不整合リスク

2. **印刷品質**: プリンター環境での文字表示問題
3. **データ移行**: 既存データへの影響
4. **テスト範囲**: 広範囲な回帰テストの必要性

### 12.3 運用上の考慮事項
1. **ユーザー教育**: 新フォーマットの説明・周知
2. **移行期間**: 旧フォーマットとの並行運用
