# 井関物流 受払管理システム基本設計書 改修版

## 改修概要
本文書は、井関物流受払管理システムの基本設計に対する改修要件を反映した設計書です。

### 改修要件
1. **自動計算機能**: 単価×数量で金額を自動計算
2. **入力促進機能**: 未入力項目の背景色変更による入力促進
3. **金額フィールド保護**: 金額の手入力禁止（グレーアウト）
4. **単位項目追加**: 請求書用の単位フィールド新設
5. **単位入力必須化**: 単位未入力時のエラー表示

## 1. システム概要

### 1.1 システム化目的
井関物流株式会社様で使用している受払管理システムがWindowsXP環境でしか動作しないため、Windowsの新バージョンに対応させると共に従来の機能をリメイクし、さらにWindowsのユーザインターフェースに対応した以下の機能を実装することを目的とする。

**改修により追加される機能**:
- 請求処理の自動化・効率化
- 入力検証機能の強化
- ユーザビリティの向上

### 1.2 機能要件（改修版）

#### 基本機能
- 受入実績登録
- 払出実績登録
- 取引先マスター登録
- 部品マスター登録
- 単価マスター登録
- **請求マスター登録（改修対象）**
- 納入先マスター登録
- 定数マスター登録

#### 改修対象機能詳細

**請求マスター登録機能の改修**:
1. **自動計算機能**
   - 単価×数量による金額の自動計算
   - リアルタイム計算処理
   - 四捨五入による金額調整

2. **入力検証機能**
   - 必須フィールドの背景色制御
   - 未入力項目の視覚的警告
   - 入力完了時の色彩復元

3. **UI制御機能**
   - 金額フィールドの読み取り専用化
   - 単位選択コンボボックスの追加
   - フィールド保護機能

4. **データ整合性機能**
   - 単位入力必須化
   - エラーメッセージ表示
   - 保存前検証処理

## 3. データベース設計（改修版）

### 3.1 主要テーブル変更

#### T_SEIKYU（請求テーブル）改修
**新規追加フィールド**:
- **TANI**（単位）: VARCHAR(10) NOT NULL
  - 用途: 請求明細の数量単位を格納
  - 制約: CHECK制約による値制限
  - 初期値: 既存データは「その他」で初期化

**既存フィールドの制約強化**:
- TANKA（単価）: NOT NULL, > 0
- SURYO（数量）: NOT NULL, > 0
- KINGAKU（金額）: 自動計算値、手入力禁止

### 3.2 データ整合性ルール
1. **計算整合性**: KINGAKU = TANKA × SURYO
2. **必須入力**: TANI フィールドの入力必須化
3. **参照整合性**: 取引先マスターとの外部キー制約維持

## 5. 業務フロー（改修版）

### 5.1 請求マスター登録フロー
```
開始
  ↓
画面表示・初期化
  ↓
基本情報入力（取引先、請求日等）
  ↓
明細情報入力
  ├─ 品名入力
  ├─ 単価入力 → 背景色制御 → 自動計算実行
  ├─ 数量入力 → 背景色制御 → 自動計算実行
  ├─ 単位選択 → 背景色制御
  └─ 金額表示（自動計算結果）
  ↓
入力検証
  ├─ 必須項目チェック
  ├─ データ型チェック
  ├─ 業務ルールチェック
  └─ 計算整合性チェック
  ↓
エラーあり？ → Yes → エラー表示 → 明細情報入力へ戻る
  ↓ No
データベース更新
  ↓
完了メッセージ表示
  ↓
終了
```

### 5.2 エラーハンドリングフロー
1. **入力時エラー**
   - 背景色による視覚的警告
   - フォーカス移動制御
   - ツールチップによる説明表示

2. **保存時エラー**
   - 詳細エラーメッセージ表示
   - エラー項目のハイライト
   - 修正箇所への誘導

3. **システムエラー**
   - ログ出力
   - ユーザー向けエラー表示
   - 安全な処理中断
