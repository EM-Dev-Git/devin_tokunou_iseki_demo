# 受払管理システム DB論理設計書_20250606

## 改修概要
本文書は、井関物流受払管理システムのデータベース設計に対する改修要件を反映した設計書です。

### 改修要件
1. **単位フィールド追加**: T_SEIKYUテーブルにTANI（単位）フィールドを追加
2. **制約追加**: 新規フィールドの制約設定
3. **インデックス最適化**: 検索性能向上のためのインデックス追加
4. **データ移行**: 既存データの互換性確保
5. **自動計算対応**: 金額フィールドの計算値整合性確保

### 改修背景
**2025年3月発生事案を受けた再発防止対応**
- **発生事案**: 熊本生産グループでの発送運賃請求内容入力漏れによる会計処理ミス
- **対応方針**: データベース構造改善による入力精度向上とデータ品質確保

## テーブル設計

### T_SEIKYU（請求テーブル）改修版

#### テーブル概要
請求に関する情報を管理するテーブルです。改修により単位フィールドが追加され、自動計算機能に対応します。

#### テーブル定義
```sql
CREATE TABLE T_SEIKYU (
    SEIKYU_NO           VARCHAR(20)     NOT NULL,           -- 請求番号
    TORIHIKISAKI_CD     VARCHAR(10)     NOT NULL,           -- 取引先コード
    TORIHIKISAKI_NAME   VARCHAR(100)    NOT NULL,           -- 取引先名
    SEIKYU_DATE         DATE            NOT NULL,           -- 請求日
    HINMEI              VARCHAR(100)    NOT NULL,           -- 品名
    TANKA               DECIMAL(10,2)   NOT NULL,           -- 単価
    SURYO               DECIMAL(10,2)   NOT NULL,           -- 数量
    TANI                VARCHAR(10)     NOT NULL,           -- 単位（新規追加）
    KINGAKU             DECIMAL(12,2)   NOT NULL,           -- 金額
    GOUKEI              DECIMAL(12,2)   NULL,               -- 合計
    SAKUSEI_DATE        DATETIME        NOT NULL DEFAULT GETDATE(), -- 作成日時
    KOSHIN_DATE         DATETIME        NOT NULL DEFAULT GETDATE(), -- 更新日時
    SAKUSEI_USER        VARCHAR(50)     NOT NULL,           -- 作成者
    KOSHIN_USER         VARCHAR(50)     NOT NULL,           -- 更新者
    
    CONSTRAINT PK_T_SEIKYU PRIMARY KEY (SEIKYU_NO),
    CONSTRAINT CK_T_SEIKYU_TANKA CHECK (TANKA >= 0),
    CONSTRAINT CK_T_SEIKYU_SURYO CHECK (SURYO > 0),
    CONSTRAINT CK_T_SEIKYU_TANI CHECK (TANI IN ('個', '本', '台', '式', 'kg', 'm', '㎡', 'その他')),
    CONSTRAINT CK_T_SEIKYU_KINGAKU CHECK (KINGAKU >= 0)
);
```

#### フィールド詳細

##### 1. SEIKYU_NO（請求番号）
- **データ型**: VARCHAR(20)
- **制約**: PRIMARY KEY, NOT NULL
- **説明**: 請求を一意に識別する番号
- **形式**: YYYYMMDD + 連番（例：2025060600001）

##### 2. TORIHIKISAKI_CD（取引先コード）
- **データ型**: VARCHAR(10)
- **制約**: NOT NULL
- **説明**: 取引先を識別するコード
- **参照**: 取引先マスターテーブル

##### 3. TORIHIKISAKI_NAME（取引先名）
- **データ型**: VARCHAR(100)
- **制約**: NOT NULL
- **説明**: 取引先の正式名称
- **連動**: 取引先コード選択時に自動設定

##### 4. SEIKYU_DATE（請求日）
- **データ型**: DATE
- **制約**: NOT NULL
- **説明**: 請求書の発行日
- **形式**: YYYY-MM-DD

##### 5. HINMEI（品名）
- **データ型**: VARCHAR(100)
- **制約**: NOT NULL
- **説明**: 請求対象の品目名称

##### 6. TANKA（単価）
- **データ型**: DECIMAL(10,2)
- **制約**: NOT NULL, CHECK (TANKA >= 0)
- **説明**: 品目の単価（円）
- **精度**: 小数点以下2桁まで

##### 7. SURYO（数量）
- **データ型**: DECIMAL(10,2)
- **制約**: NOT NULL, CHECK (SURYO > 0)
- **説明**: 請求対象の数量
- **精度**: 小数点以下2桁まで

##### 8. TANI（単位）【新規追加】
- **データ型**: VARCHAR(10)
- **制約**: NOT NULL, CHECK制約
- **説明**: 数量の単位
- **選択肢**: '個', '本', '台', '式', 'kg', 'm', '㎡', 'その他'
- **初期値**: 'その他'（既存データ移行時）
- **改修内容**: 
  - 新規フィールドとして追加
  - 必須入力項目として設定
  - CHECK制約による値の制限

##### 9. KINGAKU（金額）
- **データ型**: DECIMAL(12,2)
- **制約**: NOT NULL, CHECK (KINGAKU >= 0)
- **説明**: 請求金額（単価×数量の計算結果）
- **精度**: 小数点以下2桁まで
- **改修内容**: 自動計算値の整合性確保

##### 10. GOUKEI（合計）
- **データ型**: DECIMAL(12,2)
- **制約**: NULL許可
- **説明**: 請求書全体の合計金額

##### 11. SAKUSEI_DATE（作成日時）
- **データ型**: DATETIME
- **制約**: NOT NULL, DEFAULT GETDATE()
- **説明**: レコード作成日時

##### 12. KOSHIN_DATE（更新日時）
- **データ型**: DATETIME
- **制約**: NOT NULL, DEFAULT GETDATE()
- **説明**: レコード最終更新日時

##### 13. SAKUSEI_USER（作成者）
- **データ型**: VARCHAR(50)
- **制約**: NOT NULL
- **説明**: レコード作成者のユーザーID

##### 14. KOSHIN_USER（更新者）
- **データ型**: VARCHAR(50)
- **制約**: NOT NULL
- **説明**: レコード最終更新者のユーザーID

## 制約設計

### CHECK制約

#### 1. 単価制約
```sql
CONSTRAINT CK_T_SEIKYU_TANKA CHECK (TANKA >= 0)
```
- **目的**: 負の単価を防止
- **説明**: 単価は0以上の値のみ許可

#### 2. 数量制約
```sql
CONSTRAINT CK_T_SEIKYU_SURYO CHECK (SURYO > 0)
```
- **目的**: 0以下の数量を防止
- **説明**: 数量は正の値のみ許可

#### 3. 単位制約（新規追加）
```sql
CONSTRAINT CK_T_SEIKYU_TANI CHECK (TANI IN ('個', '本', '台', '式', 'kg', 'm', '㎡', 'その他'))
```
- **目的**: 単位の値を制限
- **説明**: 定義された単位のみ許可
- **改修内容**: 新規制約として追加

#### 4. 金額制約
```sql
CONSTRAINT CK_T_SEIKYU_KINGAKU CHECK (KINGAKU >= 0)
```
- **目的**: 負の金額を防止
- **説明**: 金額は0以上の値のみ許可

## トリガー設計

### 更新日時自動設定トリガー
```sql
CREATE TRIGGER TR_T_SEIKYU_UPDATE_DATE
ON T_SEIKYU
AFTER UPDATE
AS
BEGIN
    SET NOCOUNT ON;
    
    UPDATE T_SEIKYU 
    SET KOSHIN_DATE = GETDATE()
    FROM T_SEIKYU t
    INNER JOIN inserted i ON t.SEIKYU_NO = i.SEIKYU_NO;
END;
```

### 金額計算整合性チェックトリガー（新規追加）
```sql
CREATE TRIGGER TR_T_SEIKYU_AMOUNT_CHECK
ON T_SEIKYU
AFTER INSERT, UPDATE
AS
BEGIN
    SET NOCOUNT ON;
    
    -- 金額計算の整合性チェック
    IF EXISTS (
        SELECT 1 
        FROM inserted 
        WHERE ABS(KINGAKU - (TANKA * SURYO)) > 0.01
    )
    BEGIN
        RAISERROR('金額が単価×数量の計算結果と一致しません。', 16, 1);
        ROLLBACK TRANSACTION;
    END;
END;
```

## データ移行仕様

### 既存データ移行

#### 1. TANIフィールド追加
```sql
-- フィールド追加（NULL許可で一時的に追加）
ALTER TABLE T_SEIKYU 
ADD TANI VARCHAR(10) NULL;

-- 既存データに初期値設定
UPDATE T_SEIKYU 
SET TANI = 'その他' 
WHERE TANI IS NULL;

-- NOT NULL制約追加
ALTER TABLE T_SEIKYU 
ALTER COLUMN TANI VARCHAR(10) NOT NULL;

-- CHECK制約追加
ALTER TABLE T_SEIKYU 
ADD CONSTRAINT CK_T_SEIKYU_TANI 
CHECK (TANI IN ('個', '本', '台', '式', 'kg', 'm', '㎡', 'その他'));
```

#### 2. 金額整合性確認
```sql
-- 金額計算の整合性確認
SELECT 
    SEIKYU_NO,
    TANKA,
    SURYO,
    KINGAKU,
    (TANKA * SURYO) AS CALCULATED_AMOUNT,
    ABS(KINGAKU - (TANKA * SURYO)) AS DIFFERENCE
FROM T_SEIKYU 
WHERE ABS(KINGAKU - (TANKA * SURYO)) > 0.01;
```

#### 3. データ品質確認
```sql
-- データ品質確認クエリ
SELECT 
    COUNT(*) AS TOTAL_RECORDS,
    COUNT(CASE WHEN TANI IS NULL THEN 1 END) AS NULL_TANI_COUNT,
    COUNT(CASE WHEN TANKA <= 0 THEN 1 END) AS INVALID_TANKA_COUNT,
    COUNT(CASE WHEN SURYO <= 0 THEN 1 END) AS INVALID_SURYO_COUNT,
    COUNT(CASE WHEN KINGAKU < 0 THEN 1 END) AS INVALID_KINGAKU_COUNT
FROM T_SEIKYU;
```

### クエリ最適化

#### 1. 請求書出力用クエリ
```sql
-- 最適化されたクエリ（インデックス活用）
SELECT 
    s.SEIKYU_NO,
    s.TORIHIKISAKI_CD,
    s.TORIHIKISAKI_NAME,
    s.SEIKYU_DATE,
    s.HINMEI,
    s.TANKA,
    s.SURYO,
    s.TANI,
    s.KINGAKU
FROM T_SEIKYU s WITH (INDEX(IX_T_SEIKYU_TORIHIKISAKI_DATE))
WHERE s.TORIHIKISAKI_CD BETWEEN @TORIHIKISAKI_CD_FROM AND @TORIHIKISAKI_CD_TO
  AND s.SEIKYU_DATE BETWEEN @SEIKYU_DATE_FROM AND @SEIKYU_DATE_TO
ORDER BY s.SEIKYU_NO;
```

#### 2. 単位別集計クエリ
```sql
-- 単位別集計（新規追加機能）
SELECT 
    TANI,
    COUNT(*) AS RECORD_COUNT,
    SUM(KINGAKU) AS TOTAL_AMOUNT,
    AVG(KINGAKU) AS AVG_AMOUNT
FROM T_SEIKYU 
WHERE SEIKYU_DATE BETWEEN @DATE_FROM AND @DATE_TO
GROUP BY TANI
ORDER BY TOTAL_AMOUNT DESC;
```
